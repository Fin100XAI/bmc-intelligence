# Marathi translation style guide — BMC Intelligence Infrastructure

You are translating the interface of a BMC intelligence platform used by
commissioners, engineers, health officers and auditors of Maharashtra's municipal
corporations. The reader is a serving government officer.

## Register

Write **administrative Marathi as the Government of Maharashtra writes it**, not
conversational Marathi and not Hindi-influenced Marathi. Where the government's
own forms use a Sanskritised term and everyday speech uses another, the
government's term wins — an officer has to reconcile this screen against a file.

Keep English technical terms where Marathi administrative practice keeps them:
API, GIS, SLA (as सेवा-हमी), LED, CSV, ICU (as अतिदक्षता), डॅशबोर्ड.

## Hard rules

1. **The key must be reproduced byte-for-byte.** It is the English source string
   and it is what the lookup matches on. Never edit, trim or normalise a key.
2. **Every `{0}`, `{1}`, `{2}` placeholder in the key must appear in the value**,
   exactly once each. You may reorder them freely — Marathi puts the qualifier
   before the noun and the case marker on the noun, so reordering is usually
   required. Never invent a placeholder that is not in the key.
3. `{{double-brace}}` tokens are prompt variables. Reproduce them **unchanged**.
4. Preserve `\n` escapes, `·`, `→`, `×`, `₹`, `%`, `Δ` and any HTML entity
   (`&apos;` `&quot;`) exactly as they appear.
5. Numerals stay in **Latin digits** (12, 55, 2026) inside sentences and figures.
   Devanagari digits (१२) are used only in fixed display labels that are already
   written that way in the existing parts — when in doubt, use Latin.
6. Do not translate proper nouns: place names already in the catalogue, personal
   names, system identifiers (`decision:approve`, `REST API`, `GraphQL`).
7. Keep the register **neutral and non-accusatory**. This platform is explicit
   that an anomaly is not fraud, a risk is not guilt and a correlation is not a
   cause. Never strengthen a hedged English sentence into an assertion.

## File format

```ts
/** Marathi catalogue, part NN. Keyed by the exact English source. */
export const MR_PART_NN: Record<string, string> = {
  'English source': 'मराठी',
  'With a {0} placeholder': '{0} सह मराठी',
}
```

- A key with **no** apostrophe: single-quote it (`'Ward Performance'`).
- A key **containing** a single quote/apostrophe: wrap the key in double quotes
  (`"Ward's position": '...'`) — never escape inside single quotes.
- A key containing a double quote: keep it in single quotes (`'Status "{0}"'`).
- Long values may wrap onto the next line, indented four spaces. Do not split a
  string across two literals.
- TypeScript must compile: no duplicate keys **within your file**.
